# Целочисленная модель и битовые операции

## `Int` и фиксированная ширина

`Int` предназначен для обычных счётчиков, индексов и прикладной арифметики. Его
ширина является свойством целевой платформы и проекта:

```toml
[numeric]
int = "target"
```

`target` выбирает рекомендуемую ширину профиля цели. Текущие desktop-профили
Windows и POSIX используют `i32`. Проект может закрепить ABI явно:

```toml
[numeric]
int = "i16" # также доступны i8, i32 и i64
```

Настройка меняет только `Int`. Типы `i8/i16/i32/i64` и `u8/u16/u32/u64`
всегда имеют указанную ширину. Для протоколов, регистров, файловых форматов,
FFI и persistent data следует использовать именно fixed-width типы.
Литерал, не помещающийся в выбранный `Int`, отклоняется диагностикой
`SC-CG-302`, а не усекается C-компилятором.

`Float`, `Angle` и компоненты `Vec2/Vec3/Vec4` используют `f32`. Явный `f64`
остаётся 64-битным и использует double-варианты математических функций без
предварительного округления литерала до `f32`. `Time`, `Duration`, `ByteSize`,
`as_nanoseconds` и `as_bytes` используют точное целое представление `i64`
независимо от `Int`.

## Обычная целочисленная арифметика

Операторы `+`, `-`, `*`, `/`, `div`, `mod`, `%`, `^`, унарный `-`, а также
statements `++/--` проверяются.
Переполнение, деление на ноль, отрицательная целая степень и отрицание
минимального signed-значения завершают программу с `SC-RT-350`, а не переходят
в undefined behavior C. Литеральный нулевой делитель и литеральная отрицательная
целая степень отклоняются ещё семантическим анализом.

Вещественная арифметика `Float/f32/f64` сохраняет IEEE-поведение, включая
`NaN` и infinity. Для проверки результата служат `is_nan`, `is_finite` и
`is_infinite`.

## Литералы

Целые литералы поддерживают десятичную, двоичную, восьмеричную и
шестнадцатеричную запись. `_` можно использовать как визуальный разделитель:

```skadi
new u8 mask = 0b1111_0000
new u16 permissions = 0o0755
new u32 color = 0xFF_80_20_10
```

## Битовые функции

Битовая поверхность состоит из обычных builtins и не требует imports:

| Функция | Результат |
|---|---|
| `bit_and(a, b)` | Побитовое AND |
| `bit_or(a, b)` | Побитовое OR |
| `bit_xor(a, b)` | Побитовое XOR |
| `bit_not(value)` | Инверсия всех битов |
| `bit_shift_left(value, count)` | Логический сдвиг влево |
| `bit_shift_right(value, count)` | Логический сдвиг вправо |
| `bit_is_set(value, index)` | `Bool`: установлен ли бит |
| `bit_set(value, index)` | Копия с установленным битом |
| `bit_clear(value, index)` | Копия со сброшенным битом |
| `bit_toggle(value, index)` | Копия с переключённым битом |
| `bit_write(value, index, enabled)` | Set или clear по `Bool` |

Функции принимают только `i8/i16/i32/i64` и `u8/u16/u32/u64`. Платформенный
`Int` намеренно запрещён: ширина регистра или маски не должна меняться после
смены target profile.

```skadi
new u8 flags = 0b0000_0001
flags = bit_set(flags, 3)
flags = bit_toggle(flags, 0)

if bit_is_set(flags, 3) {
    output("ready")
}
```

Все операции возвращают новое значение и не изменяют аргумент скрыто.
Операнды binary-функций должны иметь один fixed-width тип. Литерал можно
использовать вместе с типизированным операндом, если он помещается в его тип:

```skadi
new u32 state = 0x1000
state = bit_or(state, 0xff)
```

Переменные разных ширин или signedness не смешиваются неявно. Целый литерал
можно присвоить fixed-width цели, только если он помещается в её диапазон.
Для переменной используется явное проверяемое преобразование с обязательным
обработчиком:

```skadi
new u16 raw = 240
new u8 level = 0

level = as_u8(raw) on error {
    output("level is outside u8")
}
```

Доступны `as_i8/as_i16/as_i32/as_i64` и `as_u8/as_u16/as_u32/as_u64`.
Они принимают любое числовое значение, вычисляют аргумент один раз и записывают
результат только при точном попадании в диапазон. Вещественное значение должно
быть конечным и не иметь дробной части. Усечение, modulo-conversion и скрытое
переполнение не выполняются; при ошибке прежнее значение target сохраняется.

`as_f32(value)` — проверяемое сужение с обязательным `on error`: аргумент должен
быть конечным и помещаться в `f32`. `as_f64(value)` — обычное безопасное
расширение числового значения и обработчика не требует.

## Явная арифметика по модулю

Когда переполнение является частью алгоритма, используйте
`wrapping_add`, `wrapping_sub`, `wrapping_mul` и `wrapping_neg`. Они работают
только с fixed-width `i8..i64/u8..u64` и возвращают младшие биты той же ширины.
`Int` намеренно не принимается: modulo-контракт не должен зависеть от target.

```skadi
new u8 sequence = 255
sequence = wrapping_add(sequence, 1) // 0

new i8 lowest = -128
lowest = wrapping_neg(lowest) // -128, тот же битовый шаблон
```

Унарный `-` для unsigned fixed-width значений запрещён. Если нужен именно
двухкомплементарный битовый результат, намерение выражается через
`wrapping_neg`.

## Сдвиги и границы

Правый сдвиг всегда логический, включая signed-типы: перед сдвигом используется
беззнаковое представление той же ширины. Например, `bit_shift_right(i8(-1), 1)`
даёт битовый шаблон `0b0111_1111`, то есть `127`.

Индекс или величина сдвига должны находиться в диапазоне `0..width-1`.
Константная ошибка обнаруживается семантическим анализом. Динамическое значение
проверяется runtime и завершается диагностикой `SC-RT-340`, а не вызывает
undefined behavior C.
